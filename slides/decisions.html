제품 형태와 진행 방식

D-001 확정

v1은 TUI, v2는 GUI

근거

오케스트레이터가 띄우는 대상(claude, codex, cursor-cli)이 전부 터미널 CLI다. 같은 터미널에 사는 편이 배포·통합이 단순하다. GUI가 실질적으로 나은 부분(dashboard, 그래프 시각화)은 코어가 안정된 뒤에 붙여도 늦지 않다.

영향

Core는 UI를 모르는 헤드리스 라이브러리여야 한다. v2에서 Shell만 교체한다. core/가 shell/을 import하면 lint 에러가 나게 경계를 강제한다.

v2에서 Core 수정이 필요하면 v1 설계가 틀린 것이고, 그 경우 GUI를 진행하지 말고 경계를 먼저 고친다.

D-002 확정

진행 방식 3종 — 자율성으로 가른다

방식성격자율성
/pingpong대화형비자율 — 사용자가 매 턴 개입
/looploop-engineering자율 반복
/graphgraph-engineering자율 DAG
근거

세 방식을 같은 축으로 갈라야 상한 정책이 일관된다. pingpong은 매 턴 사용자 승인이 있으므로 턴 제한이 불필요하고, loop와 graph는 사람이 안 보는 동안 도니까 상한이 필수다.

세 방식 공통 — 상한 도달 시 정상 중단을 정상 완료보다 먼저 검증한다.

D-003 확정

/loop의 Evaluator에 reviewer 슬롯 모델을 쓴다

Evaluator는 "결과가 기준을 충족했는가"를 판정하는 자리다. 이것을 primary와 같은 모델이 하면 자기 채점이 된다.

매트릭스가 요구하는 독립 리뷰가 루프 안에서 실현되는 유일한 자리다.

영향

루프 1사이클 비용 = primary 1회 + reviewer 1회. 비용 산정과 상한 계산이 이를 반영해야 한다.

D-004 확정 실측 근거

영향

D-005 확정

바이너리 이름은 cursor-cli, 해석은 폴백으로

이 환경에 설치된 것은 cursor와 cursor-agent뿐이고 cursor-cli는 없다.

표기

제품 문서 · UI · 설정은 cursor-cli로 통일한다.

해석

실행 시 cursor-cli를 먼저 찾고 없으면 cursor-agent로 폴백. engines.json에서 경로를 덮어쓸 수 있다.

명칭은 사용자의 선택이고, 런타임에 깨지지 않는 것은 구현의 책임이다. 둘을 분리하면 양쪽을 다 만족한다.

D-006 확인 대기

/pingpong의 "대화형" 해석

현재 해석

사용자와의 대화 — 사용자가 매 턴 개입하는 human-in-the-loop 진행.

근거

다른 둘을 "loop-engineering", "graph-engineering"이라는 규율 이름으로 부른 것과 달리 /pingpong만 성격("대화형")으로 불렀다. 자율/비자율 축에서 유일한 비자율로 두면 세 방식이 겹치지 않는다.

뒤집힐 경우

primary ↔ reviewer 교대라면 자율 실행이 되므로 최대 왕복 수, 수렴 판정 기준, 교착 시 중단 조건이 전부 필수가 된다. 상한 정책이 D-002와 달라진다.

D-008 · D-009 — 순서와 불변식

D-008 확정

라우터가 먼저, 매트릭스가 나중

라우터는 넘길 것인가, 매트릭스는 누구에게 어떤 effort로. 순서가 뒤집히면 하한선에 걸릴 작업에 Fable을 띄우게 된다.

하한선에 걸린 작업은 엔진을 띄우지 않는다. 테스트로 프로세스 spawn 0회를 확인한다.

D-009 확정

두 슬롯 + 교차 벤더 불변식

모든 배정은 primary + independent reviewer 쌍이고 vendor(primary) ≠ vendor(reviewer)를 INV-1로 강제한다.

단일 엔진 선택기로 축소하면 매트릭스의 절반을 버리는 것이고 제품의 존재 이유가 사라진다.

D-010 · D-011 — 완료의 정의와 방어선

D-010 확정

운영 기준 열이 완료의 정의

매트릭스가 이미 규정한다. 새로 발명할 이유가 없고, 발명하면 매트릭스와 어긋난다.

"성공했습니다"라는 산문은 증거가 아니다. file:line, 실행 명령과 exit code, 수정 경로, 인용 원문을 받는다.

D-011 확정 실측 근거

effort 검증은 어댑터에서 던진다

$ claude -p --effort bogus "hi"
Warning: Unknown --effort value 'bogus'
— ignoring it and using the default effort.

경고만 내고 기본 effort로 실행된다. 잘못된 effort로 돌아도 아무도 모르므로 어댑터 사전 검증이 유일한 방어선이다.

D-012 확정

codex --help 확인 결과 최상위 -p는 --profile이다. 비대화 실행 서브커맨드는 exec(별칭 e).

matrix.json을 원본 HTML에서 생성. 첫 줄에 // GENERATED. 원본 대조 테스트를 붙이고 불일치 시 빌드 실패. 수기 전사는 반드시 어긋난다.
