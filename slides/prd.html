01

문제

모델·effort 선택이 매번 즉흥 판단이다

반복되는 세 가지 비용

01

과소 배정

복잡한 RCA를 Sonnet High로 시작해 세 번 왕복하고 결국 Astra로 올린다. 왕복 비용이 처음부터 제대로 배정했을 때보다 크다.

02

과대 배정

타입 수정 하나에 Fable Max를 띄운다. 작업당 $7.63이 $0.21로 끝날 일에 나간다.

03

검증 누락

모델이 "완료했습니다"라고 하면 끝난 것으로 처리한다. 무엇이 증거인지가 업무마다 새로 정해진다.

매트릭스 v6는 이 셋에 대한 답을 이미 표로 갖고 있다. 문제는 그 표가 HTML 문서로만 존재하고 실행되지 않는다는 것이다.

제품 정의

hs-orchestrator는 매트릭스를 실행 가능한 라우터로 바꾸는 로컬 오케스트레이터다.

작업 1건을 받아 업무 유형으로 분류하고, 매트릭스대로 primary와 independent reviewer 두 슬롯에 모델·effort를 배정하고, 실제 CLI 엔진을 띄워 실행하고, 그 업무 유형이 요구하는 증거로 닫는다.

02

목표 / 비목표

목표 — 전부 측정 가능하게

#목표측정
G1배정이 매번 같은 기준으로 나온다매트릭스 11행 전부가 문서와 일치하게 배정된다
G2비싼 실행 전에 비용이 보인다승인 화면에 primary+reviewer 합산 예상 비용이 표시된다
G3독립 리뷰가 구조적으로 강제된다교차 벤더 불변식 위반이 코드 수준에서 불가능하다
G4완료 판정이 증거로 닫힌다업무별 운영 기준이 요구하는 증거 수집 후에만 완료 표시
G5무엇을 왜 그렇게 돌렸는지 남는다모든 배정·실행이 결정 로그에 2회 append된다

비목표 — 하지 않는 것

모델 벤치마킹

매트릭스는 입력이지 이 제품의 산출물이 아니다.

자체 LLM 호출

모든 실행은 설치된 CLI를 통한다. API 키를 직접 다루지 않는다.

팀 협업 · 웹 서비스

단일 사용자, 로컬 실행. 권한 모델과 멀티테넌시는 범위 밖.

IDE 통합

v1은 터미널에서 산다.

매트릭스 편집기

매트릭스는 외부에서 갱신되는 읽기 전용 입력이다.

원격 실행

로컬 프로세스만. 클라우드 세션은 범위 밖.

03

핵심 제품 판단

여기서 설계가 갈린다

판단 1

배정은 한 슬롯이 아니라 두 슬롯이다

매트릭스 11행 전부가 primary + independent reviewer 쌍이고, 전부 OpenAI × Claude 교차다. 이것이 "독립 리뷰"의 정의다.

이것을 놓치면

단일 엔진 선택기로 축소하면 매트릭스의 절반을 버리는 것이고, 제품의 존재 이유가 사라진다.

판단 2

운영 기준 열이 완료의 정의다

매트릭스는 업무 유형마다 수용 증거를 이미 규정한다.

성능 최적화

baseline / 변경 / 재측정 3점

복잡한 버그 RCA

가설이 아니라 로그로 반증

테스트 설계

실패 재현 → 최소 수정 → 회귀

완료 판정 로직을 새로 발명하지 않는다. 발명하면 매트릭스와 어긋난다.

판단 3

라우터가 먼저, 매트릭스가 나중이다

/delegation-router

넘길 것인가?

누구에게 어떤 effort로?

primary + reviewer 두 슬롯의 모델과 effort

순서가 뒤집히면

하한선에 걸릴 작업(도구 호출 1~2번, 스크립트 한 줄)에 Fable을 띄우게 된다.

04

기능 요구사항

FR-1 ~ FR-11

#기능핵심
FR-1작업 분류11행 중 1행. 실패 시 "해당 없음" → 사용자에게 올림. 임의 기본 배정 금지
FR-2위임 판정§1 하한선 점검. 걸리면 배정하지 않고 "직접 처리"로 종료
FR-3두 슬롯 배정primary/reviewer 모델·effort. 교차 벤더 불변식 + L1~L5 사다리
FR-4엔진 실행비대화 모드로 CLI 실행. 스트림 · 취소 · 타임아웃
FR-5비용 표시승인 전 합산 예상 비용. "AA 측정치, 실제 지출 아님" 명시
FR-6진행 방식 3종/pingpong · /loop · /graph
FR-7tasks상태 · 배정 · 증거 · 누적 비용
FR-8dashboard실행 중 · 배정 분포 · 누적 비용 · 성공/재시도 추이
FR-9세션 조회codex agents + claude agents 통합
FR-10PR / MR 조회gh-axi 우선, gh 폴백
FR-11결정 로그라우터 §7 스키마. 착수 시 1차, 검증 후 같은 id로 2차 append

진행 방식 3종 — 자율성으로 가른다

방식성격핵심 요구
/pingpong대화형 — 비자율턴마다 사용자 확인, 중간 개입으로 방향 수정 가능
/looploop-engineering — 자율Goal·Planner·Executor·Evaluator·Critic·Recovery 분리, 최대 반복 수 필수
/graphgraph-engineering — 자율노드별 독립 배정, 순환 검출 필수, 부분 실패 전파 규칙

세 방식 공통: 사이클마다 근거·변경·검증을 남기고, 검증 없이 다음으로 넘어가지 않으며, 최대 시도 도달 시 사람에게 올린다.

05

릴리스 · 지표 · 위험

릴리스 단계

v1

TUI

FR-1 ~ FR-11 전부. 터미널 UI.

완료 판정
실제 작업 1건이 분류 → 배정 → 실행 → 증거 수집까지 사람 개입 없이 통과

v2

GUI

v1의 코어를 그대로 쓰고 셸만 교체.

완료 판정
GUI에서 v1과 동일한 시나리오가 통과

v1의 코어(분류·라우팅·어댑터·진행 방식)는 UI에 의존하지 않는 헤드리스 라이브러리여야 한다. v2에서 재작성이 필요하면 v1 설계가 틀린 것이다.

성공 지표

100%
매트릭스 11행 배정 일치율
0
교차 벤더 위반
0
실행 전 비용 미표시 경로
0
증거 없이 완료된 작업
0%
결정 로그 2차 append 누락

전부 0 아니면 100이다. 애매한 중간값을 두지 않는다.

위험

위험영향완화
반복 방식의 무한 루프비용이 직접 나간다최대 반복 수 없이는 구현하지 않는다. 누적 비용 상한에서 강제 중단
claude --effort 오타가 조용히 기본값으로 실측잘못된 effort로 실행되고 아무도 모름어댑터가 CLI에 넘기기 전에 검증하고 실패시킨다
Cursor가 Astra·Haiku 미지원 실측11행 중 7행에서 대체 불가모델별 가용성 테이블. 불가 조합은 대체 후보에서 제외
매트릭스 원본 갱신구현 테이블과 불일치원본 HTML 대조 테스트. 불일치 시 빌드 실패
좀비 CLI 프로세스비용·리소스 누수취소가 자식 프로세스를 실제로 죽이는지 테스트
매트릭스에 없는 업무 유형임의 배정"해당 없음"은 사용자에게 올린다. 기본 배정을 만들지 않는다

미해결 질문

  1. 매트릭스에 없는 업무 유형이 반복해서 들어오면 행을 추가할 것인가, 계속 사용자에게 올릴 것인가
  2. 누적 비용 상한의 기본값
  3. /loop를 Claude Code 내장 스킬 위에 얹을 것인가 자체 구현할 것인가
  4. v2 GUI의 기술 선택 (v1 완료 후 결정)

→ 결정 근거와 번복 시 영향은 DECISIONS 덱에서.
