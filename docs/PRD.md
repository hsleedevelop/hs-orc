## 1. 문제

개발 작업마다 어떤 모델을 어떤 effort로 돌릴지가 매번 즉흥 판단이다. 세 가지 비용이 반복해서 발생한다.

1. **과소 배정** — 복잡한 RCA를 Sonnet High로 시작해 세 번 왕복하고 결국 Astra로 올린다. 왕복 비용이 처음부터 제대로 배정했을 때보다 크다.
2. **과대 배정** — 타입 수정 하나에 Fable Max를 띄운다. 작업당 $7.63이 $0.21로 끝날 일에 나간다.
3. **검증 누락** — 모델이 "완료했습니다"라고 말하면 끝난 것으로 처리한다. 업무 유형별로 무엇이 증거인지가 매번 새로 정해진다.

「GPT-5.6 x Claude 8모델 실무 사용 매트릭스 v6」은 이 세 가지에 대한 답을 이미 표로 갖고 있다. 문제는 그 표가 **HTML 문서로만 존재하고 실행되지 않는다**는 것이다.

## 2. 제품 한 줄 정의

**hs-orchestrator는 매트릭스를 실행 가능한 라우터로 바꾸는 로컬 오케스트레이터다.** 작업 1건을 받아 업무 유형으로 분류하고, 매트릭스대로 primary와 independent reviewer 두 슬롯에 모델·effort를 배정하고, 실제 CLI 엔진을 띄워 실행하고, 그 업무 유형이 요구하는 증거로 닫는다.

## 3. 사용자

단일 사용자다. 20년 경력 시니어 엔지니어가 자기 개발 작업을 로컬에서 돌린다. 팀 기능, 권한 모델, 멀티테넌시는 범위 밖이다.

### 비목표

- 모델 성능 벤치마킹. 매트릭스는 입력이지 이 제품의 산출물이 아니다.
- 자체 LLM 호출. 모든 실행은 설치된 CLI(`claude`, `codex`, `cursor-cli`)를 통한다. API 키를 직접 다루지 않는다.
- 팀 협업, 웹 서비스, 원격 실행.
- IDE 통합. v1은 터미널에서 산다.
- 매트릭스 편집기. 매트릭스는 외부에서 갱신되는 읽기 전용 입력이다.

## 5. 핵심 제품 판단

### 5.1 배정은 한 슬롯이 아니라 두 슬롯이다

매트릭스 11행 전부가 `primary + independent reviewer` 쌍이고 **전부 OpenAI×Claude 교차**다. 이것이 "독립 리뷰"의 정의다. 단일 엔진 선택기로 축소하면 매트릭스의 절반을 버리는 것이고, 제품의 존재 이유가 사라진다.

### 5.2 `운영 기준` 열이 완료의 정의다

매트릭스는 업무 유형마다 수용 증거를 이미 규정한다 — "baseline / 변경 / 재측정 3점", "가설이 아니라 로그로 반증", "실패 재현 → 최소 수정 → 회귀". 완료 판정 로직을 새로 발명하지 않고 이 열을 그대로 쓴다.

### 5.3 라우터가 먼저, 매트릭스가 나중이다

`/delegation-router`와 매트릭스는 다른 질문에 답한다.

- **delegation-router**: 이 작업을 남에게 **넘길 것인가** (§1 하한선 → 네 갈래)
- **매트릭스**: 넘긴다면 **누구에게 어떤 effort로**

순서가 뒤집히면 하한선에 걸릴 작업(도구 호출 1~2번, 스크립트 한 줄)에 Fable을 띄우게 된다. 하한선 점검이 배정보다 **앞**이다.

### 5.4 상향은 사다리를 탄다

어려워지면 즉시 최상위로 가지 않는다. **근거 보강 → effort 상향 → 모델 상향 → reviewer 추가** 순서다. `L1 Luna Mid/Haiku Low` → `L2 Terra High/Sonnet High` → `L3 Sol High/Opus High` → `L5 Astra Max/Fable Max + independent review`.

### 5.5 근거 등급을 섞지 않는다

Terminal-Bench 4.0(독립 벤치마크, model+agent harness 구성), Artificial Analysis(독립 분석), 매트릭스 배치(operating policy)는 서로 다른 등급이다. UI에서 섞어 표시하지 않고, TB4의 Astra 58.2 대 Fable 57.9 같은 0.3pp 차이로 우열을 표시하지 않는다.

## 6. 기능 요구사항

### FR-1 작업 분류

작업 설명을 받아 매트릭스 11행 중 하나로 분류한다. 분류 실패 시 "해당 없음"으로 떨어뜨리고 사용자에게 올린다 — 임의 기본 배정을 만들지 않는다. 사용자가 분류를 수동으로 덮어쓸 수 있다.

### FR-2 위임 판정

`/delegation-router` §1 하한선을 점검한다. 걸리면 배정하지 않고 "직접 처리" 판정으로 종료한다. 안 걸리면 네 갈래(①하향 ②유지 ③부분상향 ④전체승격) 중 하나를 붙여 배정으로 넘긴다.

### FR-3 두 슬롯 배정

매트릭스에서 primary와 reviewer의 모델·effort를 읽는다. 교차 벤더 불변식을 검사하고 위반 시 실패시킨다. L1~L5 사다리에 따른 상향/하향을 지원한다.

### FR-4 엔진 실행

배정된 모델을 실행할 CLI 엔진을 고르고 비대화 모드로 띄운다. 진행 상황을 스트림으로 UI에 흘린다. 취소와 타임아웃을 지원한다.

### FR-5 비용 표시

실행 승인 전에 primary+reviewer 합산 예상 비용을 보여준다. 값은 AA 벤치마크 측정치이며 실제 지출이 아님을 화면에 명시한다.

### FR-6 진행 방식 3종

| 방식 | 성격 | 핵심 요구 |
|---|---|---|
| `/pingpong` | 대화형 — 사용자가 매 턴 개입 | 턴마다 사용자 확인, 중간 개입으로 방향 수정 가능 |
| `/loop` | loop-engineering — 자율 반복 | Goal·Planner·Executor·Evaluator·Critic·Recovery 분리, 최대 반복 수 필수 |
| `/graph` | graph-engineering — 자율 DAG | 작업을 노드로 쪼개 의존성 순서 실행, 노드별 독립 배정, 순환 검출 필수 |

셋 모두: 사이클마다 근거·변경·검증을 남기고, 검증 없이 다음으로 넘어가지 않으며, 최대 시도 도달 시 사람에게 올린다.

### FR-7 tasks

작업 목록. 상태(대기/실행/검증/완료/실패), 배정된 모델·effort, 수집된 증거, 누적 비용.

### FR-8 dashboard

현재 실행 중인 것, 최근 배정 분포, 누적 비용, 업무 유형별 성공/재시도 추이.

### FR-9 세션·서브에이전트 조회

`codex agents`와 `claude agents`로 로컬에 살아 있는 전체 에이전트 세션을 한 화면에 모은다.

### FR-10 PR / MR 조회

열린 PR·MR과 CI 상태를 조회한다. `gh-axi`를 우선하고 `gh`를 폴백으로 둔다.

### FR-11 결정 로그

`~/.claude/logs/delegation-router.jsonl`에 라우터 §7 스키마로 append한다. 착수 시 1차(`status:"decided"`, `outcome:"pending"`), 검증 후 같은 `id`로 2차. 갱신이 아니라 append다.

## 7. 릴리스 단계

| 단계 | 범위 | 완료 판정 |
|---|---|---|
| **v1 — TUI** | FR-1~FR-11 전부. 터미널 UI | 실제 작업 1건이 분류→배정→실행→증거 수집까지 사람 개입 없이 통과 |
| **v2 — GUI** | v1의 코어를 그대로 쓰고 셸만 교체 | GUI에서 v1과 동일한 시나리오가 통과 |

**v1의 코어(분류·라우팅·어댑터·진행 방식)는 UI에 의존하지 않는 헤드리스 라이브러리로 만든다.** v2에서 재작성이 필요하면 v1 설계가 틀린 것이다.

## 8. 성공 지표

- 매트릭스 11행 배정 일치율 100% (테이블 테스트)
- 교차 벤더 위반 0건 (불변식)
- 실행 전 비용 미표시 경로 0건
- 증거 없이 완료로 표시된 작업 0건
- 결정 로그 2차 append 누락률 0%

## 9. 위험

| 위험 | 영향 | 완화 |
|---|---|---|
| 반복 방식의 무한 루프 | **비용이 직접 나간다** | 최대 반복 수 없이는 구현하지 않는다. 누적 비용 상한에서 강제 중단 |
| `claude --effort` 오타가 조용히 기본값으로 떨어짐 (실측 확인) | 잘못된 effort로 실행되고 아무도 모름 | 어댑터가 CLI에 넘기기 **전에** 검증하고 실패시킨다 |
| Cursor가 Astra·Haiku를 지원하지 않음 (실측 확인) | 11행 중 7행에서 대체 불가 | 모델별 가용성 테이블을 두고, 불가한 조합은 대체 후보에서 제외 |
| 매트릭스 원본이 갱신됨 | 구현 테이블과 불일치 | 원본 HTML 대조 테스트. 불일치 시 빌드 실패 |
| 좀비 CLI 프로세스 | 비용과 리소스 누수 | 취소가 자식 프로세스를 실제로 죽이는지 테스트 |
| 매트릭스에 없는 업무 유형 | 임의 배정 | "해당 없음"은 사용자에게 올린다. 기본 배정을 만들지 않는다 |

## 10. 미해결 질문

1. 매트릭스에 없는 업무 유형이 반복해서 들어오면 행을 추가할 것인가, 계속 사용자에게 올릴 것인가
2. 누적 비용 상한의 기본값
3. `/loop`를 Claude Code 내장 `/loop` 스킬 위에 얹을 것인가 자체 구현할 것인가 (SPEC §6.2 참조)
4. v2 GUI의 기술 선택 (v1 완료 후 결정)
