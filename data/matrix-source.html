Page 1 · reading guide

8모델 역할 구조

OpenAI는 Luna, Terra, Sol, Astra 순으로, Claude는 Haiku, Sonnet, Opus, Fable 순으로 업무 난도와 자율 실행 범위를 구분합니다. 실제 repo, agent harness, tool 권한과 수용 기준이 결과를 바꿉니다.

  • 벤치마크는 출발점이며, 설계에는 단일 점수가 없습니다.
  • 테스트는 생성량이 아니라 실패 재현, 수정, 회귀 방지까지 확인합니다.
  • 고위험 변경은 모델 합의 대신 로그, diff, test, 배포 관측으로 확정합니다.

Page 2 · external benchmarks

Terminal-Bench 4.0과 AA composite

Terminal-Bench는 66개의 terminal engineering task 해결률을, Artificial Analysis는 10개 혼합 평가를 제공합니다. TB4는 Haiku 공개 listing이 없지만, AA current max snapshot은 Astra 53, Fable 53*, Opus 51, Sol 47, Terra 42, Sonnet 38, Luna 37, Haiku 17입니다.

  • TB4: Astra 58.2 · Fable 57.9 · Opus 53.9 · Sol 37.3
  • TB4: Terra 21.5 · Luna 17.3 · Sonnet 12.4 · Haiku not listed
  • * Fable AA row는 fallback 포함 구성입니다.

Page 3 · primary matrix

업무별 primary와 reviewer

짧은 변경은 Luna/Haiku, 일반 구현은 Terra/Sonnet, 복합 구현은 Sol/Opus, 최고난도·장기 작업은 Astra/Fable을 중심으로 둡니다. 이 배치는 benchmark result가 아닌 operating policy입니다.

대규모 레거시 분석과 장기 마이그레이션은 Fable이 primary, Astra가 reviewer인 구성이 기본입니다.

Page 4 · quick selection

상향 순서

문제가 어려워지면 즉시 가장 강한 모델로 옮기지 않습니다. 먼저 코드·로그·재현 조건을 보강하고, 그 다음 effort, 모델, reviewer 순으로 상향합니다.

  • L1: Luna Mid / Haiku Low
  • L2: Terra High / Sonnet High
  • L3: Sol High / Opus High
  • L5: Astra Max / Fable Max + independent review

Page 5 · verification pattern

작업별 최소 evidence

설계에는 제약·대안·결정 이유와 실패 시나리오를, 코드 변경에는 diff·실행 결과와 관련 test를 남깁니다. RCA는 수정 전 실패와 수정 후 통과, 성능은 같은 환경의 재측정을 요구합니다.

Page 6 · sources and limits

출처와 해석 한계

공개 leaderboard는 지속 갱신됩니다. 특정 repository 성공률이나 비공개 system prompt·tool set의 차이는 이 문서가 보장하지 않습니다. 중요한 채택은 동일 issue set 5 - 10개를 A/B 실행해 결정합니다.
